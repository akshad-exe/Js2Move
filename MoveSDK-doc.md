# MoveJS SDK — Architecture & Design Document

## Overview
MoveJS SDK is a full developer toolkit that lets developers write JavaScript-style smart contracts using a custom DSL and automatically compile, test, and deploy them as secure Move smart contracts on the Movement Network.

This project consists of:
- A custom Domain-Specific Language (DSL)
- A source-to-source compiler
- A CLI for compile/test/deploy
- A VS Code extension
- Auto-generated Move tests

---

## What We Are Building (Very Important)
**This project builds:**
- A DSL (Domain-Specific Language)
- A source-to-source compiler
- A developer SDK

**This project does NOT:**
- Compile JavaScript
- Create a VM
- Replace the Move language

**Compiler conversion:**
```
MoveJS DSL → Move Source Code
```

## Compiler Pipeline (Detailed)

### 1. DSL (Language Design)
The DSL is a restricted, statically-typed language with JavaScript-like syntax.

Example:
```js
contract Token {
  resource Balance;

  init(owner: address, supply: u64) {
    Balance[owner] = supply;
  }

  transfer(from: signer, to: address, amount: u64) {
    assert(Balance[from] >= amount);
    Balance[from] -= amount;
    Balance[to] += amount;
  }
}
```

**Key Design Rules:**
- No dynamic typing
- No async/await
- No inheritance
- No external imports
- Explicit resource ownership

---

### 2. Lexer (Tokenization)
**What the Lexer Does:** Converts raw source code into tokens.

**Input:**
```js
contract Token { resource Balance; }
```

**Output (tokens):**
```
KEYWORD(contract)
IDENTIFIER(Token)
LBRACE
KEYWORD(resource)
IDENTIFIER(Balance)
SEMICOLON
RBRACE
```

**How It Is Built:**
- Implemented using regular expressions
- Written in TypeScript
- Produces an array of tokens

> Note: The lexer only classifies text; it does not understand logic.

---

### 3. Parser (AST Builder)
**What the Parser Does:** Converts tokens into an Abstract Syntax Tree (AST).

**Example AST:**
```json
{
  "type": "Contract",
  "name": "Token",
  "resources": ["Balance"],
  "functions": [
    {
      "name": "transfer",
      "params": [...],
      "body": [...]
    }
  ]
}
```

**How It Is Built:**
- Grammar defined using PEG.js or Nearley.js
- Grammar rules define valid syntax
- Parser outputs structured AST nodes and enforces syntax correctness

---

### 4. Semantic Analyzer (Safety Engine)
**What the Semantic Analyzer Does:** Enforces Move language rules and security guarantees.

**Checks performed:**
- Resources cannot be copied
- Resources must have a single owner
- Mutating functions require `signer`
- `init()` function must exist
- No unsupported types or operations

**Example Error:**
```
ERROR: Resource Balance cannot be copied
```

**How It Is Built:**
- AST traversal (tree walk)
- Symbol table for tracking resources and variables
- Ownership tracking per function
- Static validation rules

---

### 5. Intermediate Representation (IR)
**Why IR Exists:** IR decouples the DSL from the Move language (DSL → IR → Move), allowing easier refactoring and potential future backends.

**IR Example:**
```json
{
  "operation": "TRANSFER",
  "resource": "Balance",
  "from": "from",
  "to": "to",
  "amount": "amount"
}
```

---

### 6. Code Generator (Move Output)
**What the Generator Does:** Transforms IR into valid Move code.

**Example Output:**
```move
public entry fun transfer(
  from: &signer,
  to: address,
  amount: u64
) {
  let bal = borrow_global_mut(signer::address_of(from));
  assert!(bal.value >= amount, 1);
  bal.value = bal.value - amount;
}
```

**How It Is Built:**
- Uses pre-audited Move templates
- Templates rendered using Handlebars/Mustache
- Injects IR data into templates
- Outputs `.move` files

## Auto Deploy System
**CLI Command:**
```bash
movejs deploy --network testnet
```

**What Happens Internally:**
1. Compile DSL → Move
2. Run `move build`
3. Run `move publish`
4. Capture transaction hash
5. Display deployed contract address

**Implementation details:**
- Node.js `child_process.exec`
- Reads `Move.toml` configuration
- Uses Movement network profiles

## Testing System

**DSL Tests (developer-friendly):**
```js
test("token transfer", () => {
  deploy(Token);
  assert(balance(alice) === 50);
});
```

**Generated Move Tests (auto-generated by compiler):**
```move
#[test]
fun test_transfer() {
  // setup
  // assertions
}
```

Benefits:
- Developer-friendly testing
- Native Move test compatibility
